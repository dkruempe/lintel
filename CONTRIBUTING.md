# CONTRIBUTING.md

## Introduction

Thank you for your interest in `lintel`! We accept contributions in the form of bug reports, pull requests, documentation improvements or suggestions.

## Prerequisites

- C++17-compatible compiler (CI tests GCC 13 and Clang 18)
- CMake 3.16+
- Conan 2
- Ninja
- Optional: ccache, Docker (for PostgreSQL tests), PostgreSQL (local)

## Development workflow

1. Fork or clone the repo (`https://github.com/dkruempe/lintel`)
2. Set up a local build and test environment per the build commands
3. Make changes in a feature branch
4. Check format and lint locally
5. Run the tests
6. Open a pull request against `master`

## Build and test commands

### Build (Release, like CI)

```bash
# 1. Conan dependencies
conan install . --output-folder=build --build=missing -s build_type=Release -c tools.cmake.cmaketoolchain:generator=Ninja

# 2. Configure CMake
cmake -S . -B build/build/Release \
  -DCMAKE_TOOLCHAIN_FILE=build/build/Release/generators/conan_toolchain.cmake \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER_LAUNCHER=ccache \
  -G Ninja

# 3. Build
cmake --build build/build/Release --parallel $(nproc)
```

Binaries end up in `bin/`.

### Tests

```bash
cd build/build/Release && ctest --output-on-failure --label-regex unit
```

The single test binary is `base_tests` (Catch2 + trompeloeil). PostgreSQL-dependent tests require a running Postgres instance, e.g.:

```bash
docker compose up postgres
```

(database/user/password: `test`/`test`/`test`, port `5432`)

## Format and lint

- Format check (blocking in CI): `./scripts/check-format.sh master` (checks only changed files against the base commit). Repo-wide drift: `./scripts/check-format.sh --all` (informational, blocking with `--strict`).
- clang-tidy (currently advisory in CI): `./scripts/check-tidy.sh master build/tidy` (requires a compile_commands.json without Unity build and without PCH).

Run formatting with `clang-format -i` on changed files. CI expects no new `clang-format` violations in changed files.

## Code additions

- **New test files:** must be added explicitly to the `ADD_EXECUTABLE(base_tests ...)` list in `tests/CMakeLists.txt` (no automatic discovery).
- **New source files:** must be added explicitly to `headers` resp. `sources` in `src/CMakeLists.txt` (no glob patterns).
- **Prerequisites when editing:** `config.h` is generated by CMake from `config.h.in`; `-Werror` is on by default (`lintel_WARNINGS_AS_ERRORS`). All warnings must be fixed.
- **Unity builds:** enabled by default - can mask include-order bugs; if incomplete includes are suspected, a build with Unity build disabled is worthwhile.
- **TLS certificates:** never commit private keys. Dev certificates are not in the repo; generate them locally with `./cfg/certs/generate_certs.sh` (see `cfg/certs/README.md`).

## Commit convention

The commit style in this repo is short and imperative, e.g. `docs: add README quickstart and Docker section`, `ci: bump the github-actions group with 4 updates`. Older messages are German, only the shape matters. Use it: pick a meaningful prefix (`docs:`, `ci:`, `fix:`, `feat:`, `refactor:`, ...), one logical change per commit, do not commit secrets.

## Further notes

- Work in progress and open points are not tracked in the repository; `TODO.md`, `ANALYSIS.md` and `ROADMAP.md` were removed (reasoning see `CHANGELOG.md`, section "Removed").
- The build layout follows CI (`build/build/Release`), the README points to this path.
- Before opening a pull request: check status, pass the format gate locally, run the relevant unit tests.
